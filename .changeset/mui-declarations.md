'onsystem': minor

MUI apps get a design system with no config: when a project depends on `@mui/material` and it is installed, onsystem reads MUI's components from the package's type declarations with the TypeScript checker, for MUI 5 to 9. It reads each component's props (Button's `href` signature included), the values of its string-literal props as variants (`variant`, `color`, `size`, TextField's generic `variant`), values the app adds by module augmentation or in its theme (`teal: { main }`, `components.MuiChip.variants`), the element it renders and the module that default-exports it. `check`, `check_ui` and the hook then report invented MUI components, props and variant values, skip props when `component` is set, and count a `Tooltip` with a string `title` as its child's accessible name. Palette colors, the spacing unit, border radius and font family come from the `createTheme` options the app writes out, following constants it imports by a relative path. Where the app has components of its own, those win a shared name in what the tools offer and suggest, while code that imports MUI's is checked against MUI's. `inspect` shows the library on a `library` line, and a workspace package that uses MUI is a project of its monorepo root. Libraries are adapters (`src/libraries`), so Chakra UI, Mantine, HeroUI and Radix Themes can follow.
